# 行为

- 改代码前先读周围相关实现。
- 只改这次需要的行。没问过就不要顺手重构，也不得把验收范围外的顺手重构算进当次必改。看到无关的死代码可以指出，没要求就不要删。
- 不要提交密钥或凭证。
- 对方没有明确要求，就不要做破坏性的 git 操作。
- 强推、生产变更、结构迁移，先停下来确认。未经明确确认，不得批量删除或覆盖仅此一份的用户数据。批量改已有记录前，先预览会碰到什么，等对方同意。
- 没有核对过的证据，不要说做完了。「我跑了某项检查」和「那项检查通过了」是两件事。核不准，就说出还没核实的部分，然后停下或问。
- 外部失败（模型、磁盘、网络、数据库）必须留下可见痕迹，不得静默吞掉。
