# 行为

- 改代码前先读周围相关实现。
- 只改这次需要的行。没问过就不要顺手重构，也不得把验收范围外的顺手重构算进当次必改。看到无关的死代码可以指出，没要求就不要删。
- 不要提交密钥或凭证。
- 对方没有明确要求，就不要做破坏性的 git 操作。
- 强推、生产变更、结构迁移，先停下来确认。未经明确确认，不得批量删除或覆盖仅此一份的用户数据。批量改已有记录前，先预览会碰到什么，等对方同意。
- 递归删除（`rmdir /s`、`Remove-Item -Recurse`、`rm -rf`、`git clean -fdx`、`shutil.rmtree` 等）动手前先解析目标并打印：PowerShell 用 `(Get-Item -LiteralPath $p).FullName`。三条全满足才删，不必问人：不是盘符根（`C:\`、`D:\`）和用户主目录；在当前工作区之内；目标本身不是 `ReparsePoint`。任一不满足就停下问人。工作区在 D 盘只说明可以动这个仓库，不说明可以动 D 盘。删除用 PowerShell 的 `-LiteralPath`，不要套 `cmd /c` 再转义引号；路径来自变量时先确认变量非空。联接和符号链接只删指针本身，不带 `-Recurse` 进去；不要把工作区外的目录联进工作区。工作区外的递归删除，只在对方本轮用一句话点名了那条路径时才做。
- 没有核对过的证据，不要说做完了。「我跑了某项检查」和「那项检查通过了」是两件事。核不准，就说出还没核实的部分，然后停下或问。
- 外部失败（模型、磁盘、网络、数据库）必须留下可见痕迹，不得静默吞掉。
