# 项目工作法 · 执行细节

工作法理由与原则在 `docs/方法/项目工作法.md`。这里只放动手时要核对的步骤。

## 路径与命令

| 资产 | 路径或命令 |
|------|------|
| 某篇设计目标（目标册分组） | `docs/能力/<功能名>/<功能名>设计目标.md` |
| 总表 | `docs/设计目标检查清单.md` |
| 看板卡 | `docs/看板/items/item-N.md`（页眉经脚本改，正文按普通 markdown 改） |
| 登记 / 改状态 | `npm run board -- add` / `patch` / `summary` / `next` / `get` |
| 看板页 | `npm run board:server` → http://localhost:8080/ |
| 空白模板 | 本目录 `templates/`（设计目标、检查清单、看板卡） |

新建设计目标时，先复制对应模板。不要去卡片目录里挑今天干什么。不要把讨论文稿当收件箱。没说登记，不要为了走流程去 add。修 bug、补刀有相关旧项时，写进旧卡（或挂子项），不要另开父项。口号进册要人点头，不要从讨论文稿爬进去。

`placement` 可空。若填写，只能是 `改承诺`、`新承诺`、`只记工作`。前两个必须有 `--goal`。

## 流程一：目的变了

1. 改目的不必先开卡，也不必先做成。口号可以先写入目标册。人说先登记才挂看板。
2. 用三步判断（先过目的/做法关）决定：改旧句或状态、加进旧篇、还是新开一篇。不写做法。
3. 起草文首表：实质结果置顶；拦住殿后；每条有状态（口号 / 做了一截 / 已做成）、「对比时看什么」和验证方式；项目列可空。
4. 等人确认措辞和状态。
5. 原地替换文首。同一轮改总表对应行，必要时改 `.myrules-context.md`。
6. 若看板上有进行中的项：`npm run board -- summary`，说明哪些继续 / 改范围 / 标完成。

## 流程二：借鉴现成系统

1. 只读人打算搬的那一部分代码，以及能说明「为什么」的提案、变更说明、提交记录。
2. 输出机制说明；每条标「对方写明」或「从代码推断」。
3. 等人逐项采纳 / 砍掉 / 后置。理由指向本项目当前目的。
4. 写入《功能名设计目标》，标状态，同步总表。看板需要时再补 `goal`。
5. 若学到的东西改变了目的，先走流程一。

## 流程三：写代码（仅当已经挂在某张卡上）

没有看板项就直接改，不要为了走本流程去开卡。

1. 现场写在当前卡或子项。修 bug 挂在相关旧项下，不要 add 新父项。
2. 通读周围实现。说明将改的文件、故意不做的范围。
3. 只改当次需要的行。无关问题记在卡上。
4. 行为变了就跑相关测试。
5. 对照目标汇报：形式证据；实质核验路径。禁止只说编译过了。
6. 问碰到了哪条目标、状态变了没有。做法只关卡。
7. 写下收尾行（旧格式「有 / 没有」或「未碰目标」或「碰到 ID（状态）」）。
8. 人确认实质结果后：`npm run board -- patch --id item-N --status done --set focus=false`。

## 流程四：设计目标不要写成日记

从《功能名设计目标》里删掉调试日志、走查、某日记录和做法细节，移到对应那张看板卡。口号和做了一截留在文首。

若文首出现两套对不上的目的，提议拆成两篇，等人拍板后再拆。

## 流程五：项目目标审计

人说「审计」「目标审计」或「项目目标审计」时走这里。三阶段按顺序，缺一段就停。结论写在对话里，不写进总表。

1. **收尾。** 列出全部 `status=done` 的项。每项找收尾行。缺的列出来停下。不靠聊天记忆。不审 `wont` 和进行中的项。
2. **目标册内部。** 通读总表，找出不能同时为真的句子、过具体像做法的行、状态标错的行。摊开问人。人拍板后才改文首并同步总表。曾经改过目的不是自动失败。
3. **对照现实。** 按状态对照本仓库实现。已做成的必须发生；做了一截的写清哪截有了；口号记尚未做成，句子留在册上。人给了产物路径则一并对照；没给就只审本仓库。

## 改完一轮的核对

- [ ] 没说登记，就没有为了改代码去开卡，也没有先问要不要开卡
- [ ] 若登记的是修 bug / 补刀：挂在相关旧项下，没有另开父项
- [ ] 若有当前项：现场在那张卡或子项，没有另挂指针，没有预置三节
- [ ] 若动了目标：文首已改（含状态，没有做法细节），总表已逐字同步
- [ ] 若目的句变了：`.myrules-context.md` 已改
- [ ] 看板进行中的项已说明去留
- [ ] 没有把走查或做法细节写进文首；没有把口号搬去项目卡冒充必须有活卡
- [ ] 没有把卡片目录当收件箱
- [ ] 若当次挂在看板上：形式证据和实质核验路径都在；完成后该项已 `done`，卡上有收尾行，且问过碰到哪条目标
- [ ] 若在做审计：三阶段按顺序；缺收尾行未跳到对照代码；结论未写入总表；对照按状态给结论
