# 项目工作法

完整说明见 `docs/方法/项目工作法.md`。看板不是改代码的入口。改目的、人要登记或审计时读技能 `project-method`（`.claude/skills/project-method/SKILL.md`）。

- 没说登记就直接改，不要先问要不要开卡。修 bug、改代码不必先有看板项。人要登记时：修 bug、补刀挂在相关旧项下当子项（没有子项就写进旧卡），不要另开父项。只有真正的新事才 `board add`。登记用 `npm run board -- add` / `patch`。
- 登记只要标题和几句说明，写进这张卡，不强制当时写落点。
- `docs/看板/items/item-N.md` 的页眉字段（编号、状态、focus、落点等）只经 `node scripts/board.mjs` 修改，禁止手改页眉；卡片正文按普通 markdown 改。
- 目标写在 `docs/能力/<功能名>/<功能名>设计目标.md` 的文首，只写**目标**，带状态：口号 / 做了一截 / 已做成。目标是决定走向的拍板，只写**人在场景中必须能断定什么**或**系统绝不能越过的业务硬边界**。换工程做法仍成立的实施手段（字段、路径、切篇、prompt 纪律）是做法，不进文首。对话里出现的新目标不算落地；写进对应文首（必要时改 `.myrules-context.md` 那句目的）才算。口号进册要人点头。
- 口号可以没有项目。项目做完不等于目标做成。未完成目标不必有一张活卡来承载。
- `docs/设计目标检查清单.md` 禁止人手改；该表只由模型在改了文首后同一轮逐字同步，含状态。
- 标完成时问碰到了哪条目标、状态变了没有；没碰到目标就只关卡。人说审计、目标审计或项目目标审计：按技能 `project-method` 做，缺收尾行就停。
