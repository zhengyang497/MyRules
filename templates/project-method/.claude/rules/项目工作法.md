# 项目工作法

完整说明见 `docs/方法/项目工作法.md`。看板不是改代码的入口。改目的、人要登记或审计时读技能 `project-method`（`.claude/skills/project-method/SKILL.md`）。

## 看板与领号
- 没说登记就直接改，不要先问要不要开卡。人要登记时：修 bug、补刀挂在相关旧项下当子项（没有子项就写进旧卡），不要另开父项。只有真正的新事才 `board add`。登记用 `npm run board -- add` / `patch`。
- 登记只要标题和几句说明，写进这张卡，不强制当时写落点，不预置三节，不另挂指针。不要把卡片目录或讨论文稿当收件箱。
- `docs/看板/items/item-N.md` 的页眉字段（编号、状态、focus、落点等）只经 `node scripts/board.mjs` 修改，禁止手改页眉；卡片正文按普通 markdown 改。

## 目标册
- 目标写在 `docs/能力/<功能名>/<功能名>设计目标.md` 的文首，只写**目的**，带状态：口号 / 做了一截 / 已做成。拿掉这句产品要的那件事变了，才进表。字段、路径、切篇、prompt 纪律不是目标，不进文首。
- 口号可以没有项目。项目做完不等于目标做成。未完成目标不必有一张活卡来承载。
- 走查记录、调试日志、某日现场与做法细节只进对应看板卡，不得写入文首。口号留在文首。
- 对话里出现的新目的不算落地；写进对应文首（必要时改 `.myrules-context.md` 那句目的）才算。口号进册要人点头。
- `docs/设计目标检查清单.md` 禁止人手改；该表只由模型在改了文首后同一轮逐字同步，含状态。

## 收尾与审计
- 标完成时问碰到了哪条目标、状态变了没有，并写下收尾行；没碰到目标就只关卡。
- 人说审计、目标审计或项目目标审计：按技能流程五三阶段做（收尾 → 目标册内部 → 按状态对照现实），缺收尾行就停。
- 目的调整、先登记、开一项、不知道记在哪、验收算不算做成：按技能 `project-method`。修 bug、改代码不必先有看板项。
