# 项目工作法 · 执行细节

工作法理由与原则在 `docs/方法/项目工作法.md`。这里只放动手时要核对的步骤。

## 路径与命令

| 资产 | 路径或命令 |
|------|------|
| 某篇设计目标 | `docs/能力/<功能名>/<功能名>设计目标.md` |
| 检查清单 | `docs/设计目标检查清单.md` |
| 看板卡 | `docs/看板/items/item-N.md`（页眉经脚本改，正文按普通 markdown 改） |
| 登记 / 改状态 | `npm run board -- add` / `patch` / `summary` / `next` / `get` |
| 看板页 | `npm run board:server` → http://localhost:8080/ |
| 空白模板 | 本目录 `templates/`（设计目标、检查清单、看板卡） |

新建设计目标时，先复制对应模板。看板登记后现场写在这张卡上，不另挂指针，不预置三节。不要去卡片目录里挑今天干什么。不要把讨论文稿当收件箱。

`placement` 可空。若填写，只能是 `改承诺`、`新承诺`、`只记工作`。前两个必须有 `--goal`。

## 流程一：目的变了

1. 没有看板项就先登记（标题和几句即可）。
2. 用三步判断决定：改旧篇文首、加进旧篇、还是新开一篇。只写现在就该能对质的句子。
3. 起草文首表：实质结果置顶；拦住殿后；每条有「对比时看什么」和验证方式。
4. 等人确认措辞。
5. 原地替换文首。同一轮改检查清单对应行，必要时改 `.myrules-context.md`。
6. `npm run board -- summary`，说明进行中哪些继续 / 改范围 / 标完成。

## 流程二：借鉴现成系统

1. 只读人打算搬的那一部分代码，以及能说明「为什么」的提案、变更说明、提交记录。
2. 输出机制说明；每条标「对方写明」或「从代码推断」。
3. 等人逐项采纳 / 砍掉 / 后置。理由指向本项目当前目的。
4. 写入《功能名设计目标》，同步检查清单。看板需要时再补 `goal`。
5. 若学到的东西改变了目的，先走流程一。

## 流程三：写代码

1. 确认当前 `item-N`。人说先登记、或工作明显还要被找回来时没有项就先 add。拿不准就问人，不要自行开卡。
2. 现场写在 `docs/看板/items/item-N.md`。
3. 通读周围实现。说明将改的文件、故意不做的范围；需要勾选时直接写在这张卡上。
4. 只改当次需要的行。无关问题记在卡上。
5. 行为变了就跑相关测试。
6. 对照做成标准汇报：形式证据；实质核验路径。禁止只说编译过了。
7. 问这张卡有没有现在就该能对质的长期句子。有则写入对应文首并同步检查清单。
8. 在这张卡正文写下单独一行「收尾：有」或「收尾：没有」。
9. 人确认实质结果后：`npm run board -- patch --id item-N --status done --set focus=false`。

一行能结束、不值得交代的小改不走本流程。

## 流程四：设计目标不要写成日记

从《功能名设计目标》里删掉调试日志、走查、某日记录和尚未做成的句子，移到对应那张看板卡。文首只留现行标准。

若文首出现两套对不上的目的，提议拆成两篇，等人拍板后再拆。

## 流程五：项目目标审计

人说「审计」「目标审计」或「项目目标审计」时走这里。三阶段按顺序，缺一段就停。结论写在对话里，不写进检查清单。

1. **收尾。** 列出全部 `status=done` 的项。每项在该卡正文找单独一行「收尾：有」或「收尾：没有」。缺的列出来停下。不靠聊天记忆。不审 `wont` 和进行中的项。
2. **清单内部。** 通读检查清单，找出不能同时为真的句子。摊开问人如何合并。人拍板后才改文首并同步总表。曾经改过目的不是自动失败。
3. **对照现实。** 用当时的检查清单对照本仓库实现。人给了产物路径（例如用模板新建的项目库）则一并对照；没给就只审本仓库。逐条写看了什么、是否做成。

## 改完一轮的核对

- [ ] 还要被找回来的工作有 `item-N`（登记不要求当时已有 `placement`）
- [ ] 现场在 `docs/看板/items/item-N.md`，没有另挂指针，没有预置三节
- [ ] 若动了承诺：文首已改且只含现行能对质的句子，检查清单已逐字同步
- [ ] 若目的句变了：`.myrules-context.md` 已改
- [ ] 看板进行中的项已说明去留
- [ ] 没有把走查或未做成写进设计目标
- [ ] 没有把卡片目录当收件箱
- [ ] 若写了代码：形式证据和实质核验路径都在；完成后该项已 `done`，卡上有收尾行，且问过有无长期规则
- [ ] 若在做审计：三阶段按顺序；缺收尾行未跳到对照代码；结论未写入检查清单
