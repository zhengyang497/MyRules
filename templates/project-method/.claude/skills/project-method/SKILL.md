# 项目工作法

先读 [`docs/方法/项目工作法.md`](../../../docs/方法/项目工作法.md)。模板、看板命令与逐步核对见 [reference.md](reference.md)。

人拍板意图和取舍。需要领号时会说「先登记」。你查代码事实、把口语收成标准条目。没说登记就直接改代码，不要先过看板。人要登记时改看板状态或挂子项，做目标册同步和守门。人说审计时按流程五三阶段做。不准手改卡片页眉。不准自行开父项。不准因为耗时长就新开《功能名设计目标》。不准把做法细节写进文首。不准把对话里的新目的直接当已做成。不准把卡片目录或讨论文稿当收件箱。口号进册要人点头。

## 第零步：看板不是改代码的入口

没人要求登记，直接改。不要先问「要不要开卡」。看板只是需要领号时的总账，不是所有改动必须经过的门。目标不必有项目来承载。

人要登记时：

1. 修 bug、补刀、同一块功能的后续：找到相关旧项（进行中或已 done 都行），挂成子项。不要 `board add` 一张同级新卡。本仓库若没有子项，写进旧卡正文。
2. 人说「开一项」并且确实是一件新事：才 `npm run board -- add --title "..." [--body "..."] [--focus]`。只要标题和几句说明。不要预置三节。
3. 人只说「先登记」：先按第 1 条找旧项；没有相关旧项才 add 父项。登记完若人没说开始，停下。

人没说登记，不要自行开卡，也不要自行加子项。不要用 `--plan`。

## 写进目标册时：三步判断

改目的、或收工发现碰到了目标，才问。不是登记手续。先问这句是目的还是做法。做法不要写进文首。口号可以进文首，状态标「口号」。

0. 这句是目的还是做法？拿掉它，产品要的那件事变了才算目的。做法 → 只关卡，不改目标册。
1. 是否改了已经在册上的目标？→ 改那句或改状态，同一轮同步总表；需要时 `--set placement=改承诺 --set goal=<路径>`。
2. 是否多了一句目标（含口号）？→ 能挂进现有那篇就挂；否则才新开一篇。开不开项目是另一步。需要时 `placement=新承诺`。
3. 这摊只是做法？→ 只把看板项标完成，不新开设计目标。

拿不准就摊开选项等人拍。

## 按情况进流程

没有看板项的改代码，不走下面的流程三，直接改。

| 情况 | 流程 |
|------|------|
| 目的或目标状态要改 | 流程一（先改文首和总表；口号可先入册；再扫看板进行中的项） |
| 要借鉴另一个现成系统 | 流程二 |
| 已经挂在某张卡上的工作要收工 | 流程三（写在这张卡或子项；对照目标给证据；问碰到哪条、状态变了没有） |
| 设计目标里出现走查、日志或做法细节 | 流程四（搬回对应那张卡；口号留在文首） |
| 人要审计目标 | 流程五（done 项收尾 → 目标册内部 → 按状态对照现实） |

改了任何一篇文首之后：

1. 把 `docs/设计目标检查清单.md` 对应行抄成与文首逐字相同，含状态。
2. 扫描看板进行中的项，说明哪些仍有效、哪些该改范围、哪些该标完成或废弃。
3. 若目的句变了，同步 `.myrules-context.md`。

标 `done` 之前：问碰到了哪条目标、状态变了没有。没有碰到 → 只关卡。无论有没有，都写下收尾行。旧卡「收尾：有 / 没有」仍算。新卡可写「收尾：未碰目标」或「收尾：碰到 \<ID\>（\<状态\>）」。若还没定稿或还要再拆步骤，不要标完成。

## 空转自检

目的变了却先改业务代码、一次性重活却新开设计目标、没说登记却要求先过看板、修 bug 却 add 一张新父项、人没说登记却自行开卡或加子项、登记因缺落点失败、张张卡强制三节模板、完成时只说编译过了或卡上没有收尾行、把做法细节写进文首、把切篇/字段/prompt 当成目标、把未完成目标写成必须有活卡、把项目完成写成目标做成、把卡片目录当第二张工作台、另挂现行指针、或人说审计却跳过收尾去对照代码，都是失败。停下来按对应流程重做。
