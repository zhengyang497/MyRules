# 架构内聚与耦合诊断

目的：辅助把项目架构推向高内聚、低耦合。本 skill 出图，不改代码；按图收代码、拆代码之后，架构才往那个方向走。

手段：八项能力各出一张图，按上门理由只开一项，不必先做别项。有现成 dump 就当材料用；没有就对着代码审。dump 是能力一的产物，不是另外七项的底座。

段名用现成的阶段名（备料、定位、槽位、入账），不要另造更细的一套名字。文件名里的「程序」或「模型」就是段的种类。

本仓库事实摄入的现网目录：[`docs/prompt/现状/facts流程dump/`](../../../docs/prompt/现状/facts流程dump/README.md)。

## 何时用 / 不用

用：要把架构推向高内聚、低耦合，先诊断。没点名不要去抽共用、拆文件、改入口。八项各自按上门理由开，不必先写 dump。

| 这次上门是因为 | 开 |
|----------------|----|
| 要写或补一趟流程的段、覆盖清单、裁决权标 | 能力一 流程分段与裁决权清单 |
| 输出错了或点名一步，审这个判断的方法与前提 | 能力二 单点判断方法与前提审查 |
| 多段各写一份，问哪些工序共用、哪张表留段 | 能力三 同构代码共用边界划分 |
| 要看段和段之间的代码引用方不合法 | 能力四 阶段依赖与越界调用审查 |
| 用项目时撞上硬编码，问词表、上限、合法取值钉在哪一段 | 能力五 硬编码规则归属审查 |
| 拟改覆盖清单里的一条，问会动哪些信、过尺、落盘 | 能力六 改动影响评估 |
| 桌面、命令行等入口行为不一致，问是两套账还是界面差 | 能力七 多入口行为一致性核对 |
| 评测重试账、原样再发、失败却没再跑、问某次重试是模型不稳还是程序另写一套 | 能力八 模型调用重试链路审计 |

不用：Mode M 换模型打金标和知识页四维（失败和重试必须开能力八）；只改 prompt 文案；纯函数对错已知、只差补测；写「拦截流水账」；没人要求就去实现真跑 dump 代码、去抽共用解析器、去拆文件改 import、去建全局配置中心、去改入口代码、或去改重试包装；把 dump 写成架构口号、不对照代码就宣称内聚耦合变了；拿一次运行日志或 import 图顶替改动影响评估；把桌面对命令行对照表当成能力七本身；把审查脚本标签当成能力八本身。

## 能力一：流程分段与裁决权清单

对着代码走完这一趟。能改**下一封信**或**落盘**的程序，必须出现在某一段的覆盖清单里，且只出现一次。

**写 dump 时就定三方裁决权（这刀该谁说了算）**：程序卡死、模型理解、还是抛进待审阅让人拍板。事实摄入里人不是缺少的一方，人统一通过待审阅卡片与面板确认行使裁决权，因此不需要单造一种「人段」dump。

1. 按时间编号。文件名：`序号-类型-名字.md`。类型只有程序或模型。
2. **模型段就是那封信。** 渲染稿是 dump 的一种，不要另开一套现网目录。静态夹每种模型段钉一封；重试在真跑里另占序号。
3. **程序段**固定四块：要干什么；覆盖清单；这次拿进来 / 送出去什么；程序自作主张时会留下什么。进出是改动影响评估的边（开能力六），写不清就定不了。
4. 覆盖清单按动作分类，没有的类就不写：停下、准备材料、拆回信、改写、丢掉、再问模型、失败后继续、写盘。
5. 每一条写这段**做了什么**（压缩、组信、过尺、落盘），自然语言，不写参数名顶替。不要只写材料后来送给谁。组出下一封信，本身就是一条程序。
6. 覆盖清单里凡是判断（选谁、不选谁、排第几、切哪段、认不认、修不修；透传不算）的，当场标这刀该谁说了算：**程序卡死**、**模型理解**、还是**抛进待审阅**。核对有没有程序越权替人拍板并私自落盘、有没有偷懒把硬规则甩给模型、人是不是在做机器能搞定的无谓劳动。漏标或标错，补进这一段，不要留到单点判断方法与前提审查再定。
7. 看起来同类但代码各写一份的，标「另写一份，未共用」。不必标共用。要定怎么收，开能力三。
8. 写完再对一遍代码。某步能改信或改盘，覆盖清单里却没有对应动作 → 补进某一段。判断没有裁决权标 → 同样补进这一段。

维基 Stage 1–4 的信不塞进事实夹；事实段若消费分析稿的发布日，只写消费，不展开那封信。

## 能力二：单点判断方法与前提审查

一次只审一个。对着代码还原方法。有该流程 dump 就落到对应段当对照；没有不补写，直接审。读者是不知道这段代码存在的人。

判断节点：程序或模型在这里主动决定选谁、不选谁、排第几、切哪段、认不认、修不修。透传不算。本能力只审方法与前提。裁决权不是本能力的结论；要立进覆盖清单再开能力一。

按这个顺序写。缺证据就写「没有本次运行证据」，不要编。

1. **要做什么** — 一句话，业务语言。
2. **怎么做** — 方法步骤。写死的词表、加分路径、截断上限、直接排除规则都要写出来。要定这条规矩归哪一段，开能力五。
3. **这次输入长什么样** — 种子从哪来、有效信号几条、写死的表命中几条、材料形态是否踩中方法假定。没有现场时，可以另做探针，并标明这是探针不是那次运行。
4. **这次做了什么决定** — 入选（为何入选）、边缘落选、被规则直接排除。没有名单就标缺，不要用测试夹具冒充用户现场。
5. **设计前提这次成不成立** — 把方法里的假定写成可核对条目，逐条：成立 / 不成立 / 无法核对。不成立就是预期外。

读完必须能回答：方法对不对（槽 2+3+4）；这次有没有超出设计前提（槽 5）。点名了步骤就只审那一步。

形状示例见 [examples.md](examples.md)。

## 能力三：同构代码共用边界划分

一次只审一类同构动作。对着代码看各写一份的那些实现。有 dump 且标了「另写一份」，从那些段入手。不要整段对整段比，也不要做一个入口自动猜现在是哪一段。

同构动作：两段以上都在从同类材料里拿出能用的东西，代码却各写一份。能力二审的是「选谁、切哪段、认不认」；本能力审的是「复制该不该收、收到哪一层」。一条钉死的词表或上限归谁，开能力五。

按这个顺序写。

1. **看起来同类的是什么** — 一句话，业务语言。
2. **哪些工序真相同** — 相同就进共用层，只许一个主人。
3. **哪些只是很少几种切法** — 进共用层，用参数选，调用方点名；不要各写一套。
4. **哪些是认完之后那张表** — 落点要不要盖全、补丁操作合不合法、命中列表长什么样。这是编译，留在各段。
5. **因此怎么收** — 共用层收什么；各段留什么；哪种稿不准塞进来。

读完必须能回答：该共用的有没有一个主人（槽 2+3）；不该共用的有没有被焊进内核（槽 4+5）。点名了一类动作就只定这一类。本能力只出分层结论，没人要求就不要去抽代码。

形状示例见 [examples.md](examples.md)。

## 能力四：阶段依赖与越界调用审查

一次审一趟流程。用现成阶段名按时间顺序当层，对代码看谁去碰了谁的文件。有 dump 就按段序对照。读者是不知道这些文件存在的人。维基 Stage 1–4 的内部边不要混进来；跨管道只点名消费了什么。

规则：上一段只把结果交给下一段。下一段不许碰上一段内部。同级不许偷调邻居私有函数。需要同一能力：标「另写一份」，或抽到更底下的共用层（开能力三）；不许邻居互调。外壳可以往下调，下层不许去碰外壳。何为外壳，开能力七。

能力三审的是复制收在哪一层；本能力审的是这段允许依赖谁。另写一份保住边界，不算偷调。

按这个顺序写。

1. **层怎么排** — 用现成段名按时间顺序。
2. **谁在用谁** — 哪一段的代码去碰了哪一段的文件。只写这一趟相关的边。
3. **方向合不合法** — 逐条标：往下调；倒挂（时间在前的段依赖时间在后的段所在文件）；同级偷调；两段挤一个文件；外壳各调一次（主人不清，不是逆向）；跨管道借类型。
4. **看起来像逆向、其实不是** — 另写一份；编排入口往下调。
5. **因此哪几条要改层** — 只点名层界。没人要求不要拆文件、不要改 import。

读完必须能回答：有没有倒挂或同级偷调（槽 3）；另写一份有没有被误判成逆向（槽 4）。不要为了单向依赖让一段去 import 同级邻居。

形状示例见 [examples.md](examples.md)。

## 能力五：硬编码规则归属审查

一次只审一类写死的规矩。从撞上的那处硬编码读起，落到用到它的代码。有 dump 当对照。不要一次把仓库里所有常量扫完。

写死策略：代码或信里钉死的选法、切法、加分、丢掉、合法取值。不是模型临场想的，也不是人在待审阅点的。能力一写 dump 时标这刀该谁说了算；能力三审同构动作收到哪一层；本能力审这条钉死的规矩归哪一段管。

按这个顺序写。

1. **这条规矩管什么** — 一句话，业务语言。
2. **现在钉在哪** — 哪些段、哪些文件；是一份还是各钉一份。信里复述过尺取值，也算钉了一份。
3. **该归哪一段** — 只用这段的，钉在这段。多段同用：一份主人，别人只读；或另写一份并标明（本来就不是同一条策略）。不要两段各改各的还以为是同一条。
4. **不该钉死的** — 该模型认的语义、该人拍的板，不要写成词表或上限。发现这种，本能力记下「不该钉死」；要改裁决权标再开能力一，不要在本能力里假装收归属就能解决。
5. **因此怎么收** — 主人是谁；多余的钉要挪、删，还是标明另写一份。没人要求不要去改代码。

读完必须能回答：这条规矩有没有唯一主人（槽 2+3）；有没有把不该钉死的收成程序私货（槽 4）。点名了一类规矩就只定这一类。

形状示例见 [examples.md](examples.md)。

## 能力六：改动影响评估

一次只审一条动作。有 dump 就落到覆盖清单那一条，顺着「拿进来 / 送出去」走。没有 dump 就对着代码看这条吐出什么、下游谁吃，把依据写清。不要跑摄入，不要拿 import 图顶替。读者是不知道这些文件存在的人。维基 Stage 1–4 的内部边不要混进来；跨管道只点名消费了什么。

改动影响：按契约，改这一条会动哪些发给模型的信、哪些过尺、哪些落盘。能力四审的是代码允许依赖谁；本能力审的是数据进出授权影响到谁。进出写不清就标缺，不要编边。

按这个顺序写。

1. **拟改哪一条** — 哪一段覆盖清单的哪一条，一句话。
2. **本段哪项送出物会变** — 只点名这段「送出去什么」里会变的项。
3. **谁拿进来** — 下游哪段的「拿进来什么」点名了这项。没点名的不要当成边。没有 dump 就写代码里谁读了这份东西。
4. **因此会动什么** — 顺着有边的段：哪封信、哪条过尺、哪次落盘。
5. **不该变的** — 契约写明隔离的（例如缩短稿不进定位信）。
6. **看不清的** — 进出没写成项，代码也对不上，或上下游接不上。标缺，不要编边。要立进出账再开能力一。

读完必须能回答：按契约该动哪些信和盘（槽 2+3+4）；哪些被隔离（槽 5）；哪些还不是契约（槽 6）。点名了一条动作就只定这一条。本能力只出改动影响清单，没人要求不要去改代码，也不要去跑摄入。

形状示例见 [examples.md](examples.md)。

## 能力七：多入口行为一致性核对

一次只审一条已经看见的差，或一个只在某入口出现的行为。问它改不改下一封信、改不改落盘。有 dump 当对照；没有不补写。读者是不知道这些文件存在的人。桌面自动导入和命令行正式导入只是现场；冻结、评测、队列再入队也是入口。不要把对照表当成能力本身。

同一趟产品若有多个入口，能改信或改盘的是产品，只许一份，必须落在某一段覆盖清单里；读参、进度、不改账的旗标才是入口，可以各留。能力三审复制收到哪一层；能力四审代码允许依赖谁；能力六审改一条动作会牵动哪些进出。本能力审多个入口之间这一条算产品还是入口。

差分三类：产品裂开（两处都改账，做法不同）；产品只挂在一个入口（会改账，但别的入口没有）；入口才该有的差（改不了信、也改不了盘）。金标准听产品已经对的那边，不要默认某一个入口赢。先标成外壳、后来改了信或盘的，仍按产品收，不要按旧句再扩分叉。

按这个顺序写。

1. **差在哪** — 一句话，业务语言。不要写某一个入口的文件名顶替。
2. **会不会改信或改盘** — 会，就是产品；不会，才可能是入口。
3. **现在几份、挂在几个入口** — 两份做法；只挂一个入口；还是各入口各有一份读参或展示。
4. **因此归哪一类** — 产品裂开；产品只挂在一个入口；入口才该有的差。
5. **金标准听哪边** — 听已经符合「正式导入同一套账」的那边，或听覆盖清单里已经有主人的那段。
6. **因此怎么收** — 裂开的收进内核唯一主人，另一处删除或改为转发；只挂一个入口的，先问别的入口是否也该有，要有就进内核，不要就写明对照时不算这次；入口差留在壳，不进覆盖清单。没人要求不要去改代码。

读完必须能回答：这是不是两套账（槽 2+4）；该听哪边（槽 5）；该不该进某一段覆盖清单（槽 6）。点名了一条差就只定这一条。本能力只出归类，没人要求不要去改入口。

形状示例见 [examples.md](examples.md)。

## 能力八：模型调用重试链路审计

一次只审一段的一次模型调用（定位、槽位、计划、创建各算一次上门）。对着代码把第一次调用和第二次调用画成两条轨迹。第一次就失败、没有第二次，也要审，不要只审已经重试的格子。有 dump 里的「再问模型」、重试账、prompt dump，当材料；没有不补写。读者是不知道这段代码存在的人。本能力出图，不改代码，不编 Mode M 错题，不改打分脚本。正式 Mode M 见 [`docs/prompt/记录/mode-m-runbooks/README.md`](../../../docs/prompt/记录/mode-m-runbooks/README.md)；机打 `mode-m:score-retries` 是第三块现场账，不能代替落到代码的审计图。

正路 = 模型一次交卷、过尺全过时走的那条：组信 → 调用 → 拆回信 → 过尺 → 交出。重试 = 任何第二次及以后的模型调用，以及为这次调用另写的认回信、合并字段。

去信或回信是一条一条并列、彼此没有上下文的名单时：整封信再发，只抽出失败的那一条（回信里按原来那条对上），仍算同一条链路。换一封只带这一条的短信，不算。

重试主要对付模型不稳定：依据对不上、类别对不上、主语空，同一封信再走正路，下一次可能对。次要才是超时、空回信、拆不出 JSON。第三种是程序另写了一套重试，这种重试解决不了它声称的问题。第四种是失败了却没有第二次：过尺没过或通道失败后直接收口，这也是程序洞。Mode M 要查后两种。

能力一可能把「单条再问」写进覆盖清单；本能力不管清单全不全，只问第二次是不是正路，以及失败了有没有第二次。能力二问「认哪一条」方法对不对；本能力只问这刀在重试里是不是另写的。两条入口对同一段重试包装不同（记不记账），开能力七。

按这个顺序写。

1. **正路是哪一段** — 一句话：这段平时怎么组信、怎么拆、怎么过尺、交出什么。
2. **这次失败或重试声称在对付什么** — 只标一类：模型不稳（过尺没过，指望下一次交卷对）；通道（超时、空回信、拆不出）；看不清。不要在这里先定它是不是程序洞。没有第二次时，仍按这次失败来标。
3. **第二次调用是不是正路再跑一遍** — 若没有第二次，本槽写「没有第二次」，不要假装审了重试包装。有第二次则逐项标「相同」或「另写一套」：组信用的输入；发出去的信；拆回信；过尺；丢掉 / 待审 / 交出。信相同只是正路再跑的结果，不是单独一条及格线。包装函数包住的若是另一个函数，算另写一套。
4. **若另写一套，另在哪** — 点名：换了短信、名单必须剩一条才许换句、把上次的类别并进来、本地已经有收口却先再问一遍。每一处都是单独的重试设计。全是「相同」则本槽写「没有」。没有第二次则本槽写「缺的是重试本身」。
5. **这次能不能解决它声称的问题** — 正路再跑：能（模型换一版回信）。另写一套：往往不能（认不出、空转、误伤），标成 Mode M 要排的程序洞。通道失败若走的是正路再跑，标能。没有第二次：不能，标成程序洞（没设重试）。
6. **因此怎么收** — 有另写一套就删掉单独重试链路，改成「这一段原来那个函数再调用」；没有第二次就补上同一条正路再跑。Mode M 该记哪几条洞。没人要求不要去改代码。

读完必须能回答：失败了有没有第二次（槽 3）；有没有单独的重试链路（槽 3+4）；这次是模型不稳、通道，还是程序洞（槽 2+5）。点名了一段的一次模型调用就只定这一次。本能力只出审计图，没人要求不要去改重试包装。

形状示例见 [examples.md](examples.md)。

## 借口

| 借口 | 实际 |
|------|------|
| 无事不报、只记剪刀 | 判断节点每次都在判断；无事可报等于永远审不到方法 |
| 有 prompt dump 就够 | 发给模型的信不是程序段自述 |
| 覆盖清单写送给谁就行 | 压缩、组信、过尺才是程序；只写去处会漏 |
| 看起来都是抽 JSON 就算共用 | 各写一份就标「另写一份」；共用的不必标；要定收法开能力三 |
| 这段太碎，不必进 dump | 能改下一封信或改落盘就必须进某一段 |
| 再造一套比定位/槽位更细的名字 | 段名用现成阶段名 |
| 没有运行就编一份入选名单 | 只能填 1、2、5；3、4 标缺或改做标明身份的探针 |
| 审节点时再定该谁砍 | 写 dump 时覆盖清单就标程序卡死 / 模型理解 / 待审阅 |
| 审节点的目的是定三方裁决权 | 单点判断方法与前提审查只审方法与前提；裁决权是 dump 上的标 |
| 把整条链一次审完 | 一次一个节点；同构代码共用边界划分一次一类动作；硬编码规则归属审查一次一类规矩；改动影响评估一次一条动作；多入口行为一致性核对一次一条差；模型调用重试链路审计一次一段的一次模型调用 |
| 用函数名、字段名写给懂代码的人 | 读者本来就不知道这段程序存在 |
| dump 写完架构就好了 | dump 是图；高内聚低耦合是按图改代码之后才有 |
| dump 是一段所以代码也只能一个文件 | 责任归这一段；段内可以拆模块 |
| 标了另写一份就必须抽成一份 | 先拆工序；认表不同就该分开；硬焊是假低耦合 |
| 都是抽 JSON 就合成一个入口 | 入口会开始猜阶段；表意校验会漏进内核 |
| 类别不多的认表也可以按需放进通用 | 怎么切出一块完整材料可以；那张表是什么不行 |
| 思考块剥离也写进 JSON 内核职责 | 它是上一层公用函数；JSON 路径调用它，别的稿不进 JSON 解析器 |
| 另写一份就是逆向 | 复制保住边界；要不要抽共用开能力三 |
| 外壳调了三次就是下层依赖上层 | 方向对；主人不清另算 |
| 两段在一个文件所以可以互相碰内部 | 公开阶段仍是两层；挤在一起就是层界糊 |
| 为了单向依赖让局面去 import 定位过尺 | 那是同级偷调；该另写一份或开能力三 |
| 模型能猜就不用程序卡死 | 格式、日历、去重是程序职责；甩给模型是偷懒甩锅 |
| 既然有待审阅前面怎么做都行 | 待审阅是人行使裁决权的通道，不是掩盖程序越权或乱写的垃圾桶 |
| 词表写在两个文件里各改各的 | 同一条策略只许一个主人；另一处只读或标另写一份 |
| 信里写了合法取值就算过尺有主人 | 过尺取值的主人在程序段；信只复述，改取值只改一处 |
| 写死的都收进一个大配置文件 | 归段，不归全局配置垃圾桶 |
| 跑一次摄入看日志就够 | 日志是这一次碰到的分支；改动影响是契约授权能影响到的下游 |
| dump 没写拿进来就当会变 | 没点名的边标缺，不要编 |
| 改一处就默认后面全线会崩 | 先走契约；写明隔离的要列入不该变 |
| 冲击面等于 import 图 | 那是能力四；改动影响评估看进出物 |
| 只有某入口有旗标所以是外壳 | 改信或改盘仍是产品；只挂一个入口是第三类 |
| 永远听某一个入口 | 金标准听产品已经对的那边 |
| 头尾可以分叉 | 改账的终究要收进内核；旧句作废后不要再扩 |
| 第三入口可以另写一套规划 | 冻结、评测、队列偷内核，不准第三套产品 |
| 壳核就是两端对照表 | 那是现场；多入口行为一致性核对问的是产品还是入口 |
| 过尺失败不该重试 | 过尺失败正是模型不稳该重试的主因 |
| 失败了直接收口就算了 | 过尺没过或通道失败必须再走正路；没有第二次也是程序洞 |
| 原样再发就够了 | 回来之后的拆信、过尺、交出也必须是正路；只卡信仍可能另写认法 |
| 重试信可以少带几条 | 单独设计 |
| 重试可以另认一条命中 | 单独设计 |
| 名单里必须恰好一条才许换句 | 正路没有这条；整封再跑时名单几乎不会只剩一条 |
| 本地清空后再问一遍 | 第一次并没有「先问再清空」这条路 |
| 包了重试包装就算正路再跑 | 要看第二次调用的是不是原来那个函数 |
| 审查脚本标了 program-retry-pick 就算审完 | 要落到代码哪一段另写了一套，或失败了却没有第二次 |
| 第一次过尺是对的，所以重试策略也是对的 | 本项不假定正路对；只问第二次是不是同一条路 |
