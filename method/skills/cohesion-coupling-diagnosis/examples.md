# 示例

## 流程分段与裁决权清单：覆盖清单漏动作

对照：备料段已经把全文压成缩短稿给百科，覆盖清单却只写「缩短稿只给百科」。这是去处，不是动作。应写成「本段另做一份缩短稿……」。组定位去信、从围栏抽 JSON、整封再问和单条再问，同理。

定位过尺和槽位过尺从回信抽 JSON 是同一份，不必标共用。局面备料与过尺另写一份抽 JSON，标「另写一份，未与 04/06 共用」。规划、落点、章节补丁、事实抽出若也各写一份切块和修脏，同理先标，再开能力三。

覆盖清单里的判断要当场标该谁说了算。备料「按源文去已有 wiki 里找可能该更新的页」用写死的 A 股板块词给页加分：这是判断，不是透传。语义主题相关性该**模型理解**；程序只该提供中立的字面/路径索引。标成程序卡死就是越权。不要另开人段。

事实摄入现网目录见 [`docs/prompt/现状/facts流程dump/`](../../../docs/prompt/现状/facts流程dump/README.md)。

## 单点判断方法与前提审查：抽相关旧 wiki

节点：备料段里，按源文抽已有 wiki 页，供分析和计划决定更新谁、新建谁。代码入口 `searchCandidatePages`（`src/lib/ingest/candidate-search.ts`）。下面槽 1、2、5 来自读代码；槽 3 的词表部分来自对 `extractSourceTokens` 的探针（**不是**一次真实摄入）；槽 4 没有用户 wiki 现场，标缺。

### 1. 要做什么

读这篇即将摄入的源文，从已有 wiki 里找出可能该更新的旧页，列给后面的分析/计划模型。模型只能在这份名单里选「更新」；不在名单里的，计划会当成「新建」。

### 2. 怎么做

1. 从源文文件名、标题、文首小标题、正文前约 16000 字里切词。文件名和小标题权重大（约 +18），正文切词按出现次数排。
2. 丢掉停用词和一套写死的废词（「晨报」「复盘」「今日」「公司」等）。另有一套写死的**加分短语**：具身智能、人形机器人、光模块、液冷、固态电池、低空经济等 A 股板块词。
3. 用这些词去扫 `wiki/` 下所有 `.md`。标题、别名、标签、related、sources、正文命中都加分。类型为「源文档」的页直接丢掉。`wiki/index.md` 和日志页不进候选。
4. 从已命中页的 `related` 再扩一层（分数约为种子的 38%）。
5. 按分排序，最多留 50 条，写进 Stage1/Stage2 用户信的 `## Candidate Wiki Pages`。摄入阶段**不再**扫 `raw/`。
6. 源文路径在 `微信聊天` / `每日夜间交流`，或正文很长且带「重点板块/标的」时，会先切段再按段各搜一圈，然后合并。

路径名带「研报新闻」「产业链复盘」「日复盘」等会额外加分。这是写死的目录名，不是配置。

### 3. 这次输入长什么样

没有真实摄入现场。探针：把一段白糖仓单短文和一段固态电池研报短文分别交给 `extractSourceTokens`（最多 36 个词）。

仓单样本路径 `raw/仓单/2026-09-01-白糖仓单周报.md`。抽出的词以文件名切碎为主（白糖仓单周报、仓单、白糖、税仓单、单周报……），正文里「基差走强」「完税仓单增加」「郑糖近月升水」能进前 36；**加分短语命中 0**。废词过滤有效，没有「晨报」「复盘」残留。

对照的 A 股样本路径带 `研报新闻`。前 36 个词里，加分短语命中 23 条（固态电池、光模块、人形机器人、液冷订单节等，含大量切碎后的子串误命中）。

### 4. 这次做了什么决定

没有本次运行证据。仓库里的检索测试用的是「锂电」夹具，不能当成用户 wiki 的入选名单。

### 5. 设计前提这次成不成立

| 假定 | 核对 |
|------|------|
| 源文文件名/小标题能代表主题 | 探针下成立，且压过正文：文件名切碎占满词表前列，「完税」这种正文词被挤出前 36 |
| wiki 页有 aliases / tags / related 可加分 | 无法核对（没有用户 wiki 现场） |
| 加分短语覆盖这篇材料的领域 | **不成立**（仓单样本 0 命中；表是 A 股板块词） |
| 路径加分目录覆盖这篇材料的存放处 | **不成立**（样本在 `raw/仓单/`；加分目录是研报新闻、日复盘、微信聊天等） |
| 切段规则会作用在这篇上 | 仓单短文不成立：切段只认微信聊天/夜间交流路径，或超长且带「重点板块/标的」 |

预期外已经能下的结论：用仓单/商品源文时，检索会退化成「文件名切碎 + 正文字面碰运气」，A 股短语表和目录加分整段空转。这不是模型问题。入选名单对不对，要有一次真实摄入（或对该 wiki 跑一次 `searchCandidatePages`）才能填槽 4。这刀该谁说了算，看备料覆盖清单上的标（示例见上文写 dump）；本能力不改定裁决权。

## 同构代码共用边界划分：从回信拿出 JSON

同类动作：规划清单、落点表、章节补丁、事实抽出都要从模型回信里拿出 JSON，代码各写一份切围栏和修脏。思考标签剥离已经是上一层公用函数，不算 JSON 内核。

### 1. 看起来同类的是什么

模型交回一段文字，程序要从里面拿出一份能 `JSON.parse` 的完整稿。

### 2. 哪些工序真相同

剥思考标签（先过现成公用函数）；围栏优先、没有围栏再按括号切出完整 JSON；修字符串里的裸换行、单引号包裹、未转义双引号，再解析。半截、括号不配对，到这里就失败，不补括号、不猜键。

### 3. 哪些只是很少几种切法

两种：先认第一块 JSON 围栏（规划 / 落点 / 事实抽出）；多块围栏里取最后一个能解析的（章节补丁）。进共用层，用参数选，调用方点名。

### 4. 哪些是认完之后那张表

落点要不要盖全知识点、补丁操作合不合法、规划是不是创建或更新、事实抽出的命中列表长什么样。一层拆包（例如补丁外面包着数组字段）也留在那一段。

### 5. 因此怎么收

共用层：切出完整 JSON（对象或数组都能切）、修脏、解析；两种切围栏当参数。各段：认表。不准塞进来：写进 wiki 页的 FILE 切块、缺起始分隔线的 YAML 头。不要做成一个入口自动猜现在是规划、补丁还是事实抽出。

这是分层结论。没人要求就停在这里，不要去抽代码。

## 阶段依赖与越界调用审查：事实摄入

层：备料 → 抽出备料 → 定位过尺 → 槽位过尺 → 入账 → 脏格 → 待审 → 局面备料与过尺。维基 Stage 1–4 不展开。

### 1. 层怎么排

按现网 dump 01 到 12 的程序段时间顺序。模型段不算层，只夹在程序段之间。

### 2. 谁在用谁

备料不碰抽出、不碰入账。定位过尺和槽位过尺在抽出模块里，去碰入账所在的那个大文件（要词表和字段收束，但那个文件还管写盘）。入账入口写完账，顺手去调脏格。脏格和局面备料与过尺写在同一个局面文件里。局面备料与过尺自己另写一份抽 JSON，不去碰定位过尺内部。桌面、命令行、共用管道都会锁发布日并去调抽出。待审借用百科规划的卡片类型，还挂着已退役的指针判定类型。

### 3. 方向合不合法

| 边 | 判定 |
|------|------|
| 备料不碰后面 | 合法 |
| 局面另写一份抽 JSON，不碰定位过尺 | 合法（另写一份） |
| 抽出过尺碰入账写盘那个文件 | **倒挂** |
| 入账函数里调脏格 | 往下调，但两段焊在一个函数里 |
| 脏格和局面备料与过尺同一文件 | **两段挤一个文件** |
| 三个外壳都去调抽出 | 往下调；02 主人不清 |
| 待审借用规划卡片类型 | **跨管道借类型** |

### 4. 看起来像逆向、其实不是

局面抽 JSON 另写一份，不是同级偷调。三个外壳往下调抽出，不是抽出去碰外壳。路径工具不碰摄入。

### 5. 因此哪几条要改层

抽出过尺只该碰无写盘的记录定义，不该碰入账写盘文件。入账只写账，脏格由编排按段再调。脏格和局面备料与过尺不要长期挤一个文件。待审不要从百科规划里借卡片类型。不要为了单向依赖让局面去 import 定位过尺。

这是层界结论。没人要求就停在这里，不要拆文件。

## 硬编码规则归属审查：证据级只能 A/B/C/D

规矩：一条事实的证据只能标 A、B、C、D 四档；主张不得标 A。

### 1. 这条规矩管什么

程序认不认这档证据级；不在四档里的，入账过尺要挡住。

### 2. 现在钉在哪

定位组信里写成「evidenceLevel 只能是 A / B / C / D」。入账校验在账本那个文件里另有一份四档名单，主张不得用 A 也写在入账。两处没有共用同一份名单。

### 3. 该归哪一段

合法取值是程序卡死的过尺，归入账。定位信只复述这一份，不另发明一档。

### 4. 不该钉死的

哪一句算交易所摘录、哪一句算传闻，该定位模型认。不要把「怎么认档」收成程序词表；那是能力一覆盖清单上该标「模型理解」的刀。

### 5. 因此怎么收

一份四档名单钉在入账过尺；组信从这份抄进定位信。没人要求就停在这里，不要去抽常量。

## 改动影响评估：备料记下发布日线索

拟改：备料段「记下发布日线索，先不锁死」。真正锁成哪一天在抽出备料。下面只顺着现网 dump 的进出走，不是一次真跑。

### 1. 拟改哪一条

备料：记下发布日线索，先不锁死。

### 2. 本段哪项送出物会变

发布日线索。全文、指纹、缩短稿、旧 wiki 候选、旧事实上下文按契约不该因这一条而变。

### 3. 谁拿进来

抽出备料「拿进来」写的是全文、候选、分析稿（为了发布日），**没有点名发布日线索**。锁日规则写的是：指定日 → 分析稿 → 文首带标签的落款 → 文件名或路径 → 今天。后三项和备料线索的来源重叠，但是不是读备料交出来的那一份，dump 没写成边。

### 4. 因此会动什么

有契约的边目前接不上，不能把后面全线写成「会变」。

**若**抽出备料确实拿这份线索去锁日（dump 还没点名），往下才有这些边：定位信里的日期；定位过尺按「日期从哪来」把本篇时期从「是」改成不明；槽位信文首的本篇发布日；槽位过尺补发生日、并把记录上的发布日改成锁定值；入账记录的发生日与发布日；脏格按发生日标格；缺发生日的待审卡。

### 5. 不该变的

缩短稿、旧 wiki 候选、定位信里的全文、百科分析信正文。分析稿是抽出备料锁日的来源之一，改备料线索不该改分析稿本身。

### 6. dump 看不清的

抽出备料到底消费备料的线索，还是自己再从全文、路径锁一次。进出对不上，改动影响在这里断开。标缺；要补进出账再开能力一。

这是改动影响清单。没人要求就停在这里，不要去改锁日，也不要去跑摄入。

## 多入口行为一致性核对：指定发布日只有一个入口有

差：正式导入能不能指定本篇发布日。现场是命令行有 `--source-date`，桌面没有。对照见 [`docs/prompt/现状/摄入桌面与命令行壳口径.md`](../../../docs/prompt/现状/摄入桌面与命令行壳口径.md) 第 7 条（先不动）。抽出备料锁日次序第一项是「你指定的那天」。

### 1. 差在哪

正式导入能不能指定本篇发布日。

### 2. 会不会改信或改盘

会。锁成哪一天进定位信；定位过尺按「日期从哪来」可能把本篇时期从「是」改成不明；槽位信文首、补发生日、入账记录都可能被带着走。

### 3. 现在几份、挂在几个入口

不是两套锁日算法。产品输入只挂在命令行这一个入口；桌面正式导入没有对等入口。

### 4. 因此归哪一类

**产品只挂在一个入口。** 不是入口旗标。

### 5. 金标准听哪边

听抽出备料已经写下的锁日次序（指定日优先）。没有第二套做法要对齐；缺的是别的入口要不要也能指定。

### 6. 因此怎么收

要别的入口也能指定 → 指定日是抽出备料的产品输入，各入口转发进内核。不要 → 写明正式导入可以不指定日，对照「同一套账」时只开了指定发布日不算这次。先不动不等于把它当成外壳。

这是归类。没人要求就停在这里，不要去加入口控件。

## 模型调用重试链路审计：定位依据对不上之后另认回信

现场：农产品材料 MiniMax 第二次。依据句多写了「英亩」，定位过尺对不上。重试账上四条：两次对不上、两次认不出可用命中。代码里重试发整封定位信，认回信却要求「原句仍对不上时，新名单必须恰好一条才许换句」，并且按条循环再发。铜那次槽位改成只含一条的短信、计划空回信后抽出整单作废，各算另一次上门，不要塞进这篇。

### 1. 正路是哪一段

定位：整封定位信 → 拆命中名单 → 逐条看依据是否在原文、时间用语是否在窗口 → 对不上丢掉，过了交给槽位。

### 2. 这次重试声称在对付什么

模型不稳（依据对不上，指望下一次交卷抄对）。

### 3. 第二次调用是不是正路再跑一遍

| 项 | 判定 |
|------|------|
| 组信用的输入 | 相同（同一篇原文、同一封定位信） |
| 发出去的信 | 相同 |
| 拆回信 | **另写一套**（专用认回信：原句仍对不上时，只有新名单恰好一条才许换句） |
| 过尺 | 相同 |
| 丢掉 / 交出 | 相同（新名单里还是原来那句就抽出这一条）。认不出是因为上面那条认法 |

### 4. 若另写一套，另在哪

认回信专用函数：新名单必须恰好一条才许换句。正路没有这条。

### 5. 这次重试能不能解决它声称的问题

不能。整封再跑时名单不会只剩一条，于是认不出、再发、再认不出，最后仍丢掉。这是程序洞。模型多写「英亩」是另一回事，不靠这套认法来修。

### 6. 因此怎么收

定位失败就用原来的定位函数再跑；新名单里按原来那句抽出这一条即可。删掉认回信专用函数。没人要求就停在这里，不要去改抽出代码。

## 模型调用重试链路审计：空回信一次就收口

现场：规划第一次空回信，日志有通道错误，prompt dump 只有一封规划信。格子失败。没有第二次。

### 1. 正路是哪一段

规划：同一封规划信 → 拆 placements → 过尺 → 交给写页。

### 2. 这次失败或重试声称在对付什么

通道（空回信）。

### 3. 第二次调用是不是正路再跑一遍

没有第二次。

### 4. 若另写一套，另在哪

缺的是重试本身。

### 5. 这次能不能解决它声称的问题

不能。没再跑正路。这是程序洞。

### 6. 因此怎么收

规划失败就用原来那个函数再发同一封信。没人要求就停在这里，不要去改规划代码。
