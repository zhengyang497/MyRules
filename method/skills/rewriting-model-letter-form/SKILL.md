# 锁定口径，只改格式和例子

这一轮可以动**格式**和**例子**。口径句、词表、字段定义、准入、禁区、节标题用词全部不动。

不要和 `rewriting-model-letter-rules` 同一轮混用。要改口径、改标题里的字、改词表，换那一份。

**格式**是怎么排这封信：开头交什么、章节谁套谁、材料和这次的值谁先谁后、例子跟在哪。缩短节标题、压缩口径句、合并两条口径，都不是格式。

**例子**是短正反和完整输入→输出。

---

## 格式

### 1. 开头先交形状

先说这封信干什么、只交什么。形状和每个键的人话名写在最前。后面各节是在填这个形状，不要把形状埋进某一节细则里。

过关：读完开头就知道交什么。  
不过关：开头是一堆纪律，形状在信中间才出现。

### 2. 章节按这封信怎么判断来排

一节是一件独立的判断。只为某一个字段服务的细则，写在那一节下面，不要升成和它平级的一章。看目录应能看出分几步干活，不是提示主题清单，也不是 JSON 有几个键就开几章。一组同对象的细则归一节；单条细则不升小标题；开头的说明合并成段，不为每条规则立节。

信还是一堆平铺时：先读这封信里实际在说什么，把相近的归成一类，再按类开节。分类从这封信的内容来，不要拿别的信的目录来套，也不要写死一套所有信通用的章节名。

过关：只看目录，能看出这封信分几步干活。  
不过关：目录是提示主题清单；或按输出格子拆章，把成组的判断拆碎。

### 节内骨架：要求、正例、空节，按这个次序

细则节固定三段：要求在前，正例其次，空节怎么交、边界在哪收尾放最后。例子不嵌在要求句中间。标题只写对象名，不带例子、不带括注。

过关：只看一节，先读到要求，再看到需要的输出长什么样。  
不过关：要求散在例子后面；标题里带例子或括注。

### 3. 只改结构时，句子一个字都不要动

改层级、改标题从属，和改口径是两回事。说了只调结构，就冻结全部句子，包括节标题用词。可以改标题的级别（例如从与上级平级改为下级），不可以改标题里的字。

过关：diff 里只有标题级别或段落从属，句子和标题用词与改前相同。  
不过关：声称只调结构，却改写、缩短或合并了句子或标题用词。

### 4. 信封：各次都一样的、这篇材料、这次任务，分开放

角色、输出形状、口径、完整样例，换一篇材料也不该变，放 system。源文或本批材料随这篇而变，放 user。这次才注入的值（发布日、文件名、时钟）也放 user，不要写进各次共用的那一截。

这次才注入的值不要只丢一个数。标签上写清：这个值在这封信里只用来做什么，以及不能拿去干什么。源文很长时，先给材料，这些值和「只交开头那个形状」放在材料后面，避免被当成原文里的句子，或读完长文把收口忘掉。

一条作业的输入写在一起。用户侧若列出多条，每一条是一块：这条自己的原文、类别、日期挨着写。不要拆成「全部原文一张清单、全部日期另一张清单」，靠编号去对。

过关：共用那一截换一篇材料、换一个任务，字节仍一样；看见这次的值时，同一行已经写明只做什么、不做什么；长材料结束后还有一句只交开头那个形状。  
不过关：把这次才有的值写进各次共用的规范样例；这个值光秃秃写在文首，用途只写在 system 远处；两条实例靠两个编号清单对位。

### 5. 例子嵌在哪

短正反跟在那条规则后面，不单独成章。完整输入→输出放在全部口径之后，自己一节，不要插在某一条规则中间，也不要和这篇材料混在 user 里。

过关：读规则时，难分叉当场能看见对照；读完整样例时，看到的是整份作业。  
不过关：完整样例拆碎塞进各条规则；短正反拉成和字段平级的「样例章」。

## 例子

### 正例直接写出要交的东西

正例就是那份输出本身（代码块或成品行），不要用「下一行写……」的散文描述别人怎么交。反例一行对照即可。判据：蒙住例子，人能照要求写出同样的块；例子本身看不懂的，不过关。

### 6. 重要且不重复，不求全覆盖

短正反和完整输入→输出是同一批例子，摊开一起看。不要只审完整样例、把规则后的正反原样留下。现网已经写上的正反，也要过这一条。

例子只留**重要**（真容易填错的那道岔）且**互不重复**的。不要求把前面每条规则都演示到。规则句子已经能执行、或只是这批里已有例子的同类，不要再留这条正反，也不要再开一则完整样例。现网散文式例子要改写成输出块，不只是删重复。

过关：把全部短正反和全部完整样例摊开，每一条都在解一个别的例子解不开的重要分叉。  
不过关：为覆盖清单堆许多容易的情况；两条例子在解同一道岔；完整样例过了「重要且不重复」，短正反却原样全留。

### 7. 两种形式，一道岔只选一种

一种是跟在那条规则后面的短正反，只对照一个容易填错的格子。一种是规则全部写完之后的完整输入→输出，用来看多个格子怎样成套。同一道岔不要两种都写；只有两种在教不同的事时才都留。

只填一个词就会错的，用短正反。要看到几个字段一起对才暴露的，用完整样例。

过关：每一道岔只有一种形式在教。  
不过关：同一道岔既有短正反又有完整样例，且教的是同一件事。

### 8. 收例子时口径还在不在

删掉一条正反之后，看那条例子里有没有口径句没写过的限制。有，就停：这一轮不许删这条例子，也不许把限制写进口径句；把缺口报给人，改口径换 `rewriting-model-letter-rules`。例子只是把已经写清的句子再演示一遍，才可以只删例子。

过关：删掉的只是重复演示；剩下的口径句仍覆盖原来那条限制。  
不过关：为了少重复，删掉了口径句里没有的限制。

### 9. 样例写出来了，不等于过关

把输入当作业、输出当答卷，用这封信已经写下的规则逐条判。短正反和完整样例都要过。每一格都要能用这封信已经写下的规则推出来。第一稿几乎都会和规则打架；验收是改到不再打架，不是 JSON 已经写在稿子里。对不上，这一轮只改样例。规则本身错了，换 `rewriting-model-letter-rules`，不要在这一轮改规则来迁就样例。

还要核：标题和答卷是同一道题；依据是该则原文里连续出现过的原句，禁止改写、拼接、补年、补机构。

过关：换一个人只拿规则、不看你的意图，会把这份答卷判成合格。  
不过关：写完没对过规则；「正确输出」里有规则禁止的做法；标题教 A、答卷在做 B；第一稿没改就当验收。

### 10. 规则允许有时有值、有时为空的字段，正反都要有

短正反和完整样例合在一起看。同一个字段在这一批里每一条答卷都是空的，有问题：它在暗示这格永远填空。有值怎么填，该空才空。不要整列都空。

过关：该填的时候这批里有填上的答卷，该空的时候才空。  
不过关：整列都空；或为了好看每条都填；只看完整样例有值，不管短正反里该空的有没有。

### 11. 完整样例的作业要像正式那一次

输入形状和用户消息相同。标题和导语要写这封信真正在做的判断，不要写成上一封信的活。正式用户消息用哪篇材料，和样例用哪篇材料，不必是同一篇。

过关：把这则样例的输入接到正式用户消息的位置，形状对得上。  
不过关：样例缺用户消息里那些带用途的值；或在教上一阶段才做的判断。

### 12. 样例原文要厚过输出

原文里要有按规则不该交出来的句子。输出应是从里面挑出来的子集。原文若几乎句句都进了输出，这则样例没有在教「怎么选」。

过关：原文里能指出至少一句按规则不该出现在输出里。  
不过关：原文几乎是输出依据的清单一一照抄。

## 口径核

动手前把当前稿另存一份当基线。不要用现网信当基线，除非人声明比的就是现网。

**口径核** = 口径句、词表、节标题用词、加粗条目名，以及夹在口径句里、不是以「正例」「反例」起头的举例。下面这些不算口径核，可以动：

- 标题的级别（井号多少），标题用词不动
- user 里这篇材料与这次注入的值谁先谁后、收口那一句
- `### 样例` 整节
- 标题里带「正反示例」的整章
- 单独成条、以「正例」「反例」起头的条目
- 口径句末尾从「正例」或「反例」起的尾巴

两条口径话题相近，仍是两条口径。

只改例子、没动层级也没动信封时，改完跑：`node scripts/prompt-letter-lock.mjs --base <动手前.md> --next <动手后.md>`，必须退出 0。动了层级或信封时，脚本会把这些也算进 diff；这时要人工确认口径句和标题用词与基线逐字相同，不能拿脚本非 0 当「可以改口径」。

过关：口径核与基线逐字相同。  
不过关：为了少重复改了未标明正反的口径句；把节标题改短当成改格式；没对基线就当过关。

## 假过关

- 把「格式」理解成只改例子（1–5）
- 缩短节标题、压缩口径句当成改格式（3、口径核）
- 为覆盖清单堆例子；或丢掉「重要且不重复」（6）
- 只拿完整样例过「重要且不重复」，短正反一律保留（6）
- 同一道岔又写短正反又写完整样例（7）
- 收样例时删掉了口径句里没有的限制（8）
- 完整样例写出来了，但没拿规则当答卷对过（9）
- 该有值也该空的字段，样例里整列都空（10）
- 样例原文几乎句句都进了输出（12）
- 正例写成「下一行写……」的散文，不是输出块（正例输出块）
- 要求散在例子后面，或开头碎成一堆小段（节内骨架）
- 和 `rewriting-model-letter-rules` 同一轮混用
